# TASK-0167: Tenant and Platform Usage Statistics Projections

## Outcome

Tenant and platform usage views use the same dimension contract while clearly
separating current enforcement counters from historical activity and billing
projections.

## Acceptance criteria

1. Tenant and platform responses expose dimension, unit, period, limit,
   consumed, remaining, source, and freshness consistently.
2. Historical web/mobile activity is not merged into current Redis
   enforcement counters or rendered as an exact zero when unavailable.
3. Billing and statistics projections remain tenant-scoped and preserve
   package/entitlement snapshot context across package changes.
4. Source mismatch, stale, and unavailable states are visible through stable
   reconciliation codes.

## Verification

Focused API contract tests cover two tenants, package changes, current versus
historical periods, unavailable sources, and platform-admin redaction.

## Implementation completed

- Added tenant-scoped historical projections from the usage ledger.
- Exposed projections separately from current Redis enforcement snapshots on
  tenant usage and platform billing responses.
- Historical projection rows now explicitly expose nullable `limit` and
  `remaining` fields rather than implying an unavailable value is zero.
- Package catalog and tenant/platform projection contracts were verified across
  all four AiaaS tiers and two tenant IDs.

## Verification evidence

- `go test ./...` passed: 209 tests in 33 packages; focused projection and
  reconciliation tests passed.
- Tenant usage and platform billing responses preserved current versus
  historical separation and tenant isolation.
- ClickHouse outage returned `503 usage_unavailable`; Redis outage preserved
  safe fail-open usage behavior without leaking dependency details.

## Review — PASS

- Projection responses preserve source/freshness semantics and nullable
  unavailable values; no historical activity mutates Redis enforcement state.
- Package/entitlement context remains tenant-scoped and the new fields are
  backward-compatible additive JSON fields.
