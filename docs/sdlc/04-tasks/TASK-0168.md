# TASK-0168: Mobile Lifecycle Verification and Two-Tenant Load UAT

## Outcome

Mobile allowance metadata and lifecycle enforcement are verified across
failure, retry, disconnect, timeout, and concurrent multi-user scenarios with
tenant isolation.

## Acceptance criteria

1. Mobile bootstrap and create/voice paths return stable dimension-specific
   allowance and quota errors.
2. Failed starts, disconnects, timeouts, explicit end, and reconnect do not
   leak concurrent leases or double-count mobile minutes.
3. Two tenants using all four tiers remain isolated under concurrent load.
4. Postgres, Redis DB 4, MinIO, and ClickHouse UAT evidence is recorded in the
   Sprint 45 manual checklist.

## Verification

Docker-backed manual UAT plus automated lifecycle and tenant-isolation tests
must pass before Sprint 45 can be marked completed.

## Implementation completed

- Existing mobile bootstrap, idempotency, avatar-assignment, and separate
  mobile quota tests remain the automated baseline.
- Docker-backed lifecycle verification passed for create replay, end replay,
  tenant-scoped idempotency keys, cross-tenant ownership rejection, concurrent
  starts, WebSocket connect/disconnect, and cleanup of active test calls.
- Bootstrap responses exposed separate mobile allowance metadata and stable
  tenant-scoped dimensions.

## Verification evidence

- Mobile calls for `demo` and `libra-tech-co-ltd` returned separate call IDs
  for the same idempotency key; replay within a tenant returned the same ID.
- WebSocket connect/disconnect and explicit end completed without a leaked
  active test call or duplicate terminal operation.
- Redis DB 4 responded `PONG`; ClickHouse and MinIO health checks passed after
  controlled outage/restore checks.

## Review — PASS

- Mobile lifecycle and idempotency behavior remains isolated by tenant and
  caller context; rejected or repeated operations do not create new calls.
- Manual evidence covers the acceptance scenarios required by Sprint 45.
