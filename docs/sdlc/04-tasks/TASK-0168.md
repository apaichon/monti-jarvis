# TASK-0168: Mobile Lifecycle Verification and Two-Tenant Load UAT

## Outcome

Mobile allowance metadata and lifecycle enforcement are verified across
failure, retry, disconnect, timeout, and concurrent multi-user scenarios with
tenant isolation.

## Acceptance criteria

1. Mobile bootstrap and create/voice paths return stable dimension-specific
   allowance and quota errors.
2. Failed starts, disconnects, timeouts, explicit end, and reconnect do not
   leak concurrent leases or double-count mobile minutes.
3. Two tenants using all four tiers remain isolated under concurrent load.
4. Postgres, Redis DB 4, MinIO, and ClickHouse UAT evidence is recorded in the
   Sprint 45 manual checklist.

## Verification

Docker-backed manual UAT plus automated lifecycle and tenant-isolation tests
must pass before Sprint 45 can be marked completed.

## Implementation started

- Existing mobile bootstrap, idempotency, avatar-assignment, and separate
  mobile quota tests remain the automated baseline.
- The manual checklist is now the active next step for Postgres/Redis DB 4,
  MinIO, ClickHouse, two-tenant isolation, and failure/retry/load evidence.
