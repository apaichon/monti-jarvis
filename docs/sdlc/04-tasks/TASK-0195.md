# TASK-0195: Public Directory Contract + Tenant Resolve

## Outcome

Customer portal can load a **safe public list** of call-to tenants and resolve
one tenant by slug/id for entry, reusing the existing public brands directory
rules (active tenant, listed, platform_listed, KYC eligible).

## Acceptance criteria

1. `GET /api/public/brands` (and optional alias `GET /api/public/tenants` if
   implemented) returns only public-safe fields for listable tenants.
2. `GET /api/public/brands/{slug}` resolves by **slug or tenant id** and returns
   404 for unlisted / inactive / not platform-listed.
3. Response never includes secrets, admin email, KYC internals, or entitlement
   details.
4. Documented contract matches DES-0049 (pagination `limit`/`offset`/`q`,
   `items`/`total`).
5. Unit/handler tests cover: listed vs unlisted, slug vs id resolve, empty list.
6. Optional: thin customer-facing alias path is wired without duplicating store
   logic (single store method).

## Implementation notes

- Reuse `internal/store.ListPublicBrands` / `GetPublicBrand`.
- Prefer not inventing a second brand table; extend only if a missing field
  blocks the picker (e.g. display name already present).
- No schema migration required unless a seed gap blocks local demo (document
  seed/list flags instead).
