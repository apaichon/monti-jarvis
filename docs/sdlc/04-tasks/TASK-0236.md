# TASK-0236: Waiting UX, Tenant Visibility, and UAT

## Outcome

Customer-web explains the waiting state and tenant/admin surfaces can see active
and queued concurrent-call capacity.

## Acceptance Criteria

1. Customer voice UI shows waiting, position, estimated wait, timeout, cancel,
   auto-start, total calls, and busy/live status in English and Thai copy.
2. Closing the browser or pressing cancel removes the queued entry.
3. Tenant current-plan/usage view exposes active calls, queued callers, total
   calls, package concurrent limit, busy status, and recent queue timeouts.
4. Platform usage view includes the same queue snapshot for operator support.
5. Manual UAT verifies two-tenant isolation, limit=1 promotion, timeout,
   cancel, disconnect cleanup, and no over-admission.

## Review — PASS

- Customer call screen now renders queue position, total calls, active calls,
  queued callers, package limit, and busy/live state from WebSocket admission
  frames; pending callers can cancel before admission.
- Tenant current-plan response and UI expose active, queued, total, limit, busy
  status, and recent queue timeouts; platform usage inherits the same quota
  snapshot.
- Automated verification passed, and the conversation control row was simplified
  before closeout by removing keypad and replacing the generic more button with
  the selected avatar portrait.
