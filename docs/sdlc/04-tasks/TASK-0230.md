# TASK-0230: Payment Provider Config Model and Stripe Settings

## Goal

Extend the payment gateway configuration so Platform Admin can store, mask,
test, and switch `mock`, `chillpay`, and `stripe` without losing existing
ChillPay configuration.

## Acceptance Criteria

1. Payment config accepts `provider = mock|chillpay|stripe`.
2. Stripe publishable key, secret key status, webhook secret status, success URL,
   cancel URL, and callback URL are represented without exposing plaintext
   secrets in API responses or logs.
3. Existing ChillPay fields remain backward compatible and are still resolved
   from DB/env overrides.
4. `GET/PUT/POST /api/platform/payment-gateway*` support provider-specific
   validation and masked metadata.
5. Migration or `ensureSchema` delta is idempotent for existing local databases.

## Build Notes

- Added Stripe config/env fields, DB columns, masking metadata, provider-aware resolver defaults, and `.env.dev` Stripe placeholders.
- Verified with `go test ./internal/payment/... ./internal/store ./cmd/server -count=1`.
