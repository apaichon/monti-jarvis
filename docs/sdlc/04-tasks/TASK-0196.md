# TASK-0196: Customer Portal Tenant Picker + Path Context

## Done notes

Implemented in SPRINT-054 worktree.

## Outcome

`apps/customer-web` shows a tenant/brand picker when no tenant is selected.
Selecting a tenant sets in-app context (path `/t/{slug}` and session storage)
and loads workforce/theme/conversation for that tenant. Primary UX does **not**
require `?tenant_id=`.

## Acceptance criteria

1. Opening `/` (or customer root) with **no** selected tenant shows the picker
   (or empty state), not a desk that hard-fails for missing tenant.
2. Selecting a brand navigates to `/t/{slug}` (or equivalent path) and loads
   that tenant’s theme + workforce.
3. Legacy `?tenant_id=` preselects and is normalized to path/session context
   (query may be stripped after resolve).
4. Client API helpers pass selected tenant via **`X-Tenant-Id`** preferentially;
   query/body remain allowed as transport fallback where needed (WS/SSE).
5. User can change tenant (back to picker or switch control) without full app
   reinstall; prior conversation state does not leak into the new tenant desk.
6. Thai + English labels for picker chrome (title, search placeholder, empty).
7. Embed route unchanged (still embed-key based).

## Implementation notes

- Prefer SvelteKit route `src/routes/t/[slug]/+page.svelte` or shared layout
  that reuses desk components from `+page.svelte`.
- sessionStorage key suggestion: `monti_jarvis:selected_tenant` →
  `{ id, slug, name }`.
- Reuse `GET /api/public/brands` for list; `GET /api/public/theme/{tenant_id}`
  and existing workforce after selection.
