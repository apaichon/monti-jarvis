# TASK-0189: Conversation Email OTP Auto-Register

## Outcome

When the tenant setting is on, the customer conversation UI can collect email,
request OTP, verify, auto-create/reuse the customer, and bind the session so
the conversation continues under that identity.

## Acceptance criteria

1. Request/verify OTP endpoints accept conversation context and honor
   auto-register setting + domain + rate limits.
2. First successful verify creates `customers` row when missing; second reuses.
3. Session/cookie/token returned and used for subsequent chat/voice attribution.
4. Customer UI shows email → OTP steps only when setting enabled for tenant
   (discover via public or pre-session settings probe as designed).
5. Isolation: tenant A OTP cannot create tenant B customer.
6. Tests for create-on-verify, reuse, setting off, domain reject.

## Verification

```bash
go test ./internal/store ./cmd/server -count=1
cd apps/customer-web && npm run check
```
