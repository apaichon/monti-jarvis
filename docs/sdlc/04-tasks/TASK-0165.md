# TASK-0165: Dimensioned Quota Enforcement and Mobile Allowance Contract

## Outcome

Web, embed, and mobile paths use the same tenant entitlement snapshot while
reporting separate web-minute, mobile-minute, storage, concurrency, KM, and
avatar dimensions with explicit source/freshness metadata.

## Acceptance criteria

1. Mobile call minutes use a dedicated Redis DB 4 counter and do not consume
   the web/inbound minute counter.
2. Mobile bootstrap exposes the dimension rows and mobile allowance metadata;
   legacy rules-v1 packages remain compatible by mirroring their web-minute
   allowance until migrated to rules-v2.
3. Snapshot rows report `dimension`, `unit`, `period`, `limit`, `consumed`,
   `remaining`, `source`, and `freshness`; unavailable Redis values are null
   rather than fabricated zeroes.
4. Storage usage can be read from successfully stored archive objects while
   failed/deleted objects do not consume the storage dimension.
5. Redis dependency errors map to the stable `quota_unavailable` response
   without returning raw dependency details.
