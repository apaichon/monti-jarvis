# TASK-0232: Stripe Webhook Fulfillment and Reconciliation

## Goal

Verify Stripe webhooks, record provider events, fulfill paid orders through the
existing order/document/entitlement path, and expose a safe reconciliation
operation for mismatches.

## Acceptance Criteria

1. `POST /api/callbacks/stripe` verifies `Stripe-Signature` before processing.
2. `checkout.session.completed` fulfills the matching order exactly once.
3. Failed/expired checkout events mark or leave orders in the correct state
   without granting entitlement.
4. Duplicate webhook delivery is idempotent through provider event references.
5. Platform Admin can run reconciliation and see local/provider mismatch
   summaries without exposing secrets or customer payment details.

## Build Notes

- Added signed Stripe webhook verification, event idempotency, paid/failed fulfillment reuse, provider ref sync, and dry-run reconciliation.
- Added unit coverage for Stripe signature verification and currency normalization.
