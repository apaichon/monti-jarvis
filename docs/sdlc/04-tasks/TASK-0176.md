# TASK-0176: Browser Session-Storage Migration and Web Crypto Boundary

## Outcome

Remove durable plaintext session credentials from tenant and customer browser
storage while preserving safe OAuth, preview, and checkout return flows.

## Acceptance criteria

1. Refresh credentials use an HttpOnly, Secure, SameSite cookie or an approved
   equivalent documented in the design review.
2. Access tokens are memory-first; any compatibility envelope is versioned,
   expiry-bound, and encrypted with Web Crypto without persisting its key.
3. Query-string tokens are consumed once, removed from the URL, and excluded
   from logs/history where the existing flow permits.
4. Logout, expiry, tenant switch, and migration failure clear current and known
   legacy storage keys.
5. Tests prove no plaintext token remains after migration and that checkout and
   preview flows still return safely.

## Implementation update

Browser access tokens are memory-first; refresh credentials use scoped
HttpOnly cookies. Legacy local/session token keys are purged, OAuth and email
verification tokens are removed from the URL after one-time consumption, and
logout clears the browser session.
