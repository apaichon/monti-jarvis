# TASK-0183: Admin Web Promotion Grant UX

## Outcome

Platform admin web exposes a clear **promotion package grant** flow for a
tenant. Completing the form activates the plan and shows the issued tax invoice
result.

## Acceptance criteria

1. From a tenant context in admin web (entitlement page or dedicated promotion
   panel), an admin can select an active catalog package, enter a required
   reason, optionally set validity, and submit **Grant promotion**.
2. UI labels state that grant will **set the active plan** and **issue a tax
   invoice**.
3. On success, UI shows the new active plan name/slug and the tax invoice
   document number (and link to receipt/tax console when available).
4. On failure, UI shows a clear error and does not claim partial success.
5. Only authenticated platform-admin sessions can reach the action; tenant
   isolation is preserved via existing admin API client.
6. `npm run check` passes for `apps/platform-admin-web`.

## Implementation notes

- Build on existing `/admin/tenants/[id]/entitlement` or add a sibling route
  such as `/admin/tenants/[id]/promotion` — prefer extending entitlement page
  with a distinct "Promotion grant" card to avoid inventing a second tenant hub.
- Do not reuse the plain "Assign package" control for promotions without the
  invoice step; keep assign vs promotion grant distinct if both remain.
- Client types live under `apps/platform-admin-web/src/lib/api/`.
