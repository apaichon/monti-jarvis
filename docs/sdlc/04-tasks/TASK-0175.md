# TASK-0175: Referral Bonus Quota Ledger, Enforcement, and Affiliate UX

## Outcome

Sprint 46 now grants configurable, expiring referral rewards through a
tenant-scoped append-only ledger. Purchased package limits and historical usage
remain separate from bonus quota, while tenant and platform views expose the
base/bonus/total breakdown.

## Acceptance criteria

1. Platform administrators can configure fixed per-dimension rewards and
   expiry; a qualified referral grants each active rule exactly once.
2. Bonus grants, consumption, expiry, reversal, and reconciliation are
   append-only and idempotent by tenant-scoped keys.
3. Quota enforcement resolves base plus valid bonus remaining for monthly web
   minutes, mobile minutes, KM documents, storage, AI assignments, and
   concurrency without mutating package rules or usage history.
4. Tenant referral APIs expose only tenant-owned referrals and bonus balances;
   platform rules, qualification, and reversal routes remain admin protected.
5. Tenant referral UX shows the stable link, lifecycle, earned quota, use, and
   expiry; platform/tenant usage responses show base and total limits.
6. Referral clicks are captured before signup and unknown/disabled codes are
   rejected without creating tenant or reward records.

## Verification evidence

- `go test ./...` passed: 211 tests in 33 packages.
- `scripts/migrate.sh` passed against the local Postgres fixture, including
  `031_referral_bonus_quota.sql` and all reward/click/ledger tables.
- Tenant and platform `npm run check` passed; both production builds passed.
- `make build` and `git diff --check` passed.

## Review — PASS

- Base entitlements and usage events remain untouched by qualification and
  reward configuration.
- Qualification and consumption use deterministic tenant-scoped idempotency
  keys; expiry is materialized as an explicit ledger event.
- Existing tenant authorization boundaries are retained for all reward data.
