# TASK-0235: Voice WS Promotion and Release Hooks

## Outcome

`GET /ws/voice` keeps queued callers connected, promotes the first eligible
caller when a slot opens, and starts Gemini relay only after admission.

## Acceptance Criteria

1. `/ws/voice` sends queue status frames while waiting and does not consume a
   concurrent slot or start Gemini relay until admitted.
2. Call end, disconnect, timeout, failed relay start, and server-side release
   paths trigger bounded promotion.
3. Promotion uses Redis locking and re-checks package limit before handing out a
   slot.
4. Duplicate browser retries with the same admission id do not create duplicate
   queue positions.
5. Unit/integration tests cover one tenant limit=1, two queued callers, cancel,
   timeout, and restart-safe stale-entry cleanup.
