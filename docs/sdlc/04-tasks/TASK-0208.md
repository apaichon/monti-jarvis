# TASK-0208: Shared i18n Runtime + LanguageSelector

## Outcome

Each portal app has an EN/TH/JA i18n runtime (catalog + store + fallback) and a
reusable language selector control, following the product-web pattern.

## Acceptance Criteria

1. `apps/customer-web`, `apps/tenant-web`, and `apps/platform-admin-web` each
   expose `lib/i18n` with `Lang = 'en' | 'th' | 'ja'`, `setLang`, `t`/`msg`, and
   EN fallback for missing keys.
2. Preference persists under `localStorage` key `monti_jarvis:ui_lang`.
3. `LanguageSelector` (or equivalent) lists EN / TH / 日本語 with accessible
   labels and updates `document.documentElement.lang`.
4. Optional `?lang=` query initializes language (same behavior as product-web).
5. Unit or lightweight tests cover fallback + storage round-trip where practical.

## Notes

- Do not couple to S16 `tenant_settings.locale` or `ai_reply_locale`.
- product-web may keep `monti_product_lang` this sprint; document coexistence.
- Shared package optional; copy-aligned modules are acceptable for v1.
