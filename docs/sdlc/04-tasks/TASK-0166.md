# TASK-0166: Idempotent Usage Ledger and Reconciliation Runs

## Outcome

Call, mobile, KM, avatar, storage, and concurrency lifecycle events persist as
tenant-scoped logical usage events and can be replayed through bounded,
operator-controlled reconciliation runs without double counting.

## Acceptance criteria

1. Usage events are unique by `(tenant_id, idempotency_key)` and duplicate
   delivery returns the original logical result.
2. Events retain dimension, unit, amount, period, source, and entitlement
   snapshot context without storing raw provider bodies or credentials.
3. Failed starts, disconnects, timeouts, deletes, and retries do not create
   duplicate consumption; correction states are explicit.
4. Reconciliation runs validate bounded date ranges, expose source watermarks,
   mismatch/correction counts, and safe error codes.
5. Two tenants can replay the same fixture independently without cross-tenant
   reads or counter mutation.

## Verification

Postgres/Redis/MinIO/ClickHouse fixture tests, replay tests, and reconciliation
API contract tests must pass. Docker-backed UAT is required before final S45
close.
