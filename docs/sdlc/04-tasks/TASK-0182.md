# TASK-0182: Promotion Grant API + Store (Active Plan + Tax Invoice)

## Outcome

Platform admins can call a grant API that sets the tenant's **active plan**
from a catalog package and **issues a tax invoice** for that tenant in one
atomic promotion grant.

## Acceptance criteria

1. A `platform_admin` endpoint accepts tenant id, package id (active catalog
   package), optional `valid_until`, and required grant reason/notes.
2. Successful grant sets the selected package as the tenant's sole **active
   entitlement/plan** with a rules snapshot; prior active entitlement is
   superseded with an auditable promotion reason.
3. Successful grant **issues a tax invoice** document for the tenant linked to
   the promotion source (order or grant id), with immutable document number.
4. Grant is atomic: invoice failure rolls back plan activation (or compensating
   revoke); plan failure never leaves a new issued tax invoice.
5. Non-`platform_admin` receives 403; unknown tenant/package return stable 4xx;
   inactive/archived packages cannot be granted.
6. Unit/API tests cover first grant, supersede existing plan, and failure
   rollback.

## Implementation notes

- Reuse `internal/packages`, `internal/entitlements`, `internal/store` payment
  documents / billing ops — do not invent a second entitlement authority.
- Prefer a dedicated promotion grant route (e.g.
  `POST /api/platform/tenants/{tenant_id}/promotion-grants`) rather than
  silently overloading plain entitlement assign without documents.
- Promotion amount may be zero or catalog list price with 100% promo discount;
  tax policy must still use configured finance rules.
- Audit: record acting admin, reason, package id, entitlement id, tax invoice id.
