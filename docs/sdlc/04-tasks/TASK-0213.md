# TASK-0213: Light/Dark Theme Tokens and Mode Behavior

## Outcome

The call conversation page has semantic light and dark token sets that match the
approved visual direction and keep text, controls, panels, and transcript
readable in both modes.

## Done Notes

Added call-page theme state persisted under `monti_jarvis:call_theme`, default
dark mode, a visible theme toggle, semantic call tokens, and light-mode overrides
for the Sprint 59 shell. Tenant-owned avatars can now upload dedicated dark and
light portraits, and the customer call page selects the matching image for the
active mode with default portrait fallback.

## Acceptance Criteria

1. Call-page CSS uses semantic variables for surfaces, borders, text, accents,
   controls, avatar rings, waveforms, and transcript bubbles.
2. Dark mode aligns with the supplied dark mockup direction.
3. Light mode aligns with the supplied light mockup direction.
4. Theme switching or system-preference behavior is stable and does not reset
   call/session state.
5. Focus, hover, disabled, active, and error states remain visible in both
   themes.
6. Reduced-motion preference reduces avatar ring/wave animation.
7. Avatar portraits can be supplied per light/dark mode without replacing the
   default portrait.

## Notes

- Use the app's existing theme mechanism if one exists.
- Avoid expanding this into full tenant brand-theme customization.
