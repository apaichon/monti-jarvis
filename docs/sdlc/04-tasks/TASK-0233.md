# TASK-0233: Payment Gateway Admin UX and Regression Verification

## Goal

Update Platform Admin and tenant checkout UX for provider switching, then verify
Stripe sandbox and ChillPay regression paths.

## Acceptance Criteria

1. `/admin/settings/payment` shows provider selector, provider-specific fields,
   masked secret status, callback URLs, test result, and webhook/reconciliation
   status.
2. Tenant billing checkout labels and return page reflect the active provider
   without exposing provider secrets.
3. Automated tests cover config validation, Stripe webhook idempotency, and
   ChillPay regression.
4. Svelte checks/builds pass for changed admin/tenant surfaces.
5. Manual UAT documents mock, ChillPay sandbox, Stripe sandbox, duplicate
   webhook, and provider-switch behavior.

## Build Notes

- Platform Admin payment page now supports provider-specific ChillPay/Stripe fields, masked secret status, test status, webhook status, and Stripe reconciliation.
- Tenant billing checkout and return page use provider-neutral copy.
- Platform Admin payment page now supports provider-specific ChillPay/Stripe fields, masked secret status, test status, webhook status, and Stripe reconciliation.
- Tenant billing checkout and return page use provider-neutral copy.
- Automated checks/builds passed.
- Manual Stripe CLI webhook smoke uncovered the local-secret mismatch failure mode; the release documents the required `STRIPE_WEBHOOK_SECRET` alignment and includes tenant return-page provider status sync so pending Stripe orders can recover after a successful provider session.
