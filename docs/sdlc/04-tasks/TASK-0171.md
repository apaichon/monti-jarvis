# TASK-0171: Lead Capture API and Store

## Outcome

Add public lead-capture endpoints and Postgres-backed lead records with consent,
source attribution, lifecycle status, idempotent dedupe, and Redis rate limits.

## Acceptance criteria

1. `POST /api/public/leads` accepts contact/book_demo/newsletter kinds with
   validated email/company/use-case fields and required consent flag.
2. Duplicate submits within the dedupe window return the existing lead id
   without creating a second row.
3. Per-IP rate limit returns a stable error code; honeypot field is rejected.
4. Lead stores status `new`, consent timestamp, language, preferred channel,
   `utm_*`, referral code, and landing path when provided.
5. Focused unit/store tests cover validation, dedupe, and rate-limit paths.
